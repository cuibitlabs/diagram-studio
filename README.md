# Diagram Studio

**Diagrams as code, drawn properly.** 43 diagram types — architecture, C4,
sequence, flowchart, ER, Wardley, Sankey, Gantt and more — from a text file, a
Mermaid or draw.io import, or an AI agent. One deterministic layout engine
behind a browser editor, a CLI and an MCP server.

## Write a diagram your reviewers can read a diff of

```ds
architecture "Checkout platform"

customer: actor "Customer" #user
gateway: gateway "API gateway" *
orders "Orders" #go
ledger: store "Ledger" #postgresql

customer -> gateway
gateway -> orders
orders -> ledger "append"
```

```bash
npx diagram-studio convert checkout.ds checkout.svg
```

Positions are not in that file, because positions are not a decision a human
should be making by hand. The engine measures the text, sizes each box to its
content, ranks the graph and routes the connectors. Change a label and
everything re-flows; the diff stays one line.

## Why this exists

Most diagram tooling fails in one of two ways. Drag-and-drop editors produce
something good-looking that nobody updates, because updating it means half an
hour of nudging boxes. Text-to-diagram tools update fine but produce output with
a house style you cannot leave, and they solve layout by not really doing
layout — fixed node heights, connectors drawn as straight diagonals through
whatever is in the way.

This project started as a rewrite of a prototype that had exactly those
problems: it declared thirty-one types and rendered seventeen of them
identically, drew diagonal connectors through nodes, fixed every node at 88 px
tall, and
printed things that were in no model at all — a hardcoded hub label, invented
Gantt durations, scatter points positioned by `(index * 151) % 760`.

Everything here follows from fixing that. Text is measured, so boxes fit their
contents. Connectors are routed, so they go around. And **nothing is drawn that
is not in the model** — the rule the verifiers exist to enforce.

## What makes the output different

- **A real layout engine.** Text is measured against a fixed metric table rather
  than a loaded font, so a label cannot clip — and the browser, the CLI, the
  tests and the MCP server agree on geometry byte-for-byte. Connectors are
  orthogonal elbows with allocated attach points, obstacle avoidance and an A\*
  visibility-lattice fallback. Everything sits on a 4 px module.
- **It never invents content.** A chart with a missing value shows a gap and a
  note, not a zero. A funnel is proportional only when every level has a value.
  A journey draws its sentiment line only when sentiment was measured. A Gantt
  task without a duration is listed as unscheduled.
- **A visual system with a point of view.** The default is a drafting plate —
  cool vellum, graphite ink, raw sienna for the one thing to look at first — not
  the cream-paper-and-terracotta look every generated diagram arrives in. Accent
  nodes are tinted cards behind an accent border, never solid blocks. Shape
  carries semantic role, so a diagram survives greyscale.
- **Accessibility in the product, not the review.** WCAG 2.1 contrast audited
  for twelve role pairs per palette at the sizes the type scale actually uses,
  failing pairs surfaced in the editor, brand colours repaired with the hue
  preserved, four colour-vision types simulated, and accessible-name ids
  namespaced per render so two diagrams can share a page.
- **Imports that admit what they lost.** Every import records a fidelity ledger:
  source versus drawn counts, and what was collapsed, dropped or not
  representable.

## Quickstart

### The studio

```bash
npm install
npm run dev
```

Compose from a prompt, pick a structure, import a source, or write `.ds`. Drag
with snapping guides, `Ctrl+K` for the command palette, `F5` to present.
Everything autosaves locally; nothing leaves the browser.

### The CLI

```bash
diagram-studio create architecture --theme cobalt -o architecture.svg
diagram-studio import platform.drawio -o platform.svg
diagram-studio simplify platform.drawio --level balanced -o simple.svg
diagram-studio import platform.mmd --onto platform.diagram.json -o platform.svg
diagram-studio batch ./docs/diagrams --out ./docs/img --theme moss --variants
diagram-studio audit platform.diagram.json
diagram-studio report platform.diagram.json -o report.html
diagram-studio diff before.json after.json -o diff.svg
diagram-studio deck overview.json detail.json -o review.pptx
```

In: `.ds .mmd .mermaid .md .drawio .xml .json`
Out: `.ds .svg .html .mmd .drawio .json .txt .pptx .excalidraw .jsx .js`, plus
`--flat` for a Figma-ready SVG with resolved styles and named layers, and PNG
and PDF from the studio.

### With an agent

```bash
claude mcp add diagram-studio -- node ./bin/mcp-server.mjs
```

The agent gets typed tools plus the composition budget as server instructions.
`.mcp.json`, `.vscode/mcp.json` and `.cursor/mcp.json` ship with the repo, so
opening it is enough for Claude Code, VS Code Copilot agent mode and Cursor.
Claude Desktop, Windsurf, Zed, Cline, Continue and JetBrains are covered in
[`adapters/MCP.md`](adapters/MCP.md) — the config key name differs between them,
which is the usual reason an MCP server appears not to work.

Or point any agent at `skills/create-editorial-diagrams/SKILL.md`. Adapters ship
for Claude Code, Codex, Gemini CLI, Copilot, Cursor, Windsurf, Cline, Continue,
Roo Code, Amazon Q and Aider, plus `AGENTS.md` for everything else.

Things worth asking for:

- "Turn this deployment description into an executive architecture diagram."
- "Redraw `checkout.mmd` for a 16:9 technical presentation."
- "Import `platform.drawio`, simplify it to balanced detail, export SVG and PNG."
- "Match this diagram to our website and keep WCAG AA contrast."

## Importing something that already exists

```bash
diagram-studio import platform.drawio -o platform.svg
```

Mermaid (ten diagram types) and draw.io, including its compressed payload. The
redraw is not presented as a faithful copy — every import carries a ledger:

```text
Imported from draw.io: 24 shapes, 31 connectors
  drawn      22 nodes, 31 connectors
  collapsed  2 shapes into their parent container
  dropped    1 free-floating text label with no anchor
  not representable  freeform curve on "batch sync" — drawn as an elbow
```

Hand that to whoever owns the original, rather than letting them find the
differences themselves.

## It's working if…

- A node is exactly as tall as its content needs, and no two are the same height
  by coincidence.
- No connector crosses a node it does not connect to.
- You can read the whole thing in greyscale and still know what is emphasised.
- Exactly one or two things carry the accent colour.
- Nothing appears in the picture that you did not put in the model.
- `npm run check` is green, including on Windows.

If any of those is false, it is a bug — open an issue.

## When not to use it

- **A screenshot would be more honest.** If the question is "what does the UI
  look like", draw nothing.
- **The data is the point.** For a real dataset with real analysis, use a charting
  library. The chart types here are for the six numbers that belong in a
  document, not for exploration.
- **More than about a dozen elements.** The composition budget will warn you, and
  the right fix is an overview plus a detail diagram — not a smaller font.
- **You do not know the answer yet.** A diagram is a claim about how something is
  structured. If the structure is still being argued about, write the argument
  down first.

## The design system, in one paragraph

Sparse, readable, accessible, editable. One or two elements get the accent and
the rest stay quiet. Text stays text — never outlines, never an image — so it can
be searched, translated and read aloud. No shadows, no gradients, no colour
outside the token set. Semantic relationships live in the model and are never
inferred from coordinates. Every coordinate lands on the 4 px module. None of
this is decoration policy; it is what stops the output looking generated.

## Project structure

```text
src/engine/       text metrics, geometry, orthogonal router, layout algorithms
src/types/        one module per diagram type, plus the editorial guidance map
src/render/       SVG shell, skin, shapes, icons, annotations
src/theme/        colour parsing, contrast audit and repair, brand extraction
src/import|export Mermaid, draw.io, ASCII, the diagram language

                  and 215 self-contained example pages

```

## Checks

```bash
npm run check      # tests, build and verifiers
```

220 tests, plus six verifiers that fail the build on: content drawn outside the
canvas, overlapping nodes, a diagonal or node-crossing connector, geometry off
the 4 px module, a truncated or hard-broken label, a contrast pair below target,
a missing accessible name, a shadow or gradient, a literal colour outside the
token set, an over-budget accent count, a stale type reference, a stale or
orphaned example page, an example that would make a network request, and an
import that no longer renders.

CI runs all of it on Linux, Windows and macOS.

## Known limits

Stated here rather than discovered later:

- **PDF export is a high-resolution raster in a PDF wrapper**, not vector, and
  says so when you run it. When selectable text matters, place the SVG.
- **APCA contrast is deliberately not implemented.** Its constants have moved
  across draft revisions, and shipping a number people rely on that cannot be
  checked against a stable spec would be worse than not shipping it. WCAG 2.1
  only.
- **Mermaid export is lossy for the measurement types** — the writer says so in a
  header comment rather than quietly emitting a file that has lost its numbers.
- **The MCP server is tested against a scripted client**, covering handshake,
  version negotiation, notifications, batches, probes and tool errors — not
  against every IDE listed in `adapters/MCP.md`.
- **Eleven product marks are missing** — AWS, Azure, Slack, Tableau, Power BI,
  OpenAI, Twilio, SendGrid, Heroku, dbt and SonarQube — withdrawn from the
  upstream CC0 icon set at their trademark owners' request and not sourced from
  anywhere else. `UNAVAILABLE_MARKS` maps each to the concept icon to use
  instead.

## Contributing

`npm run check` must pass before a change lands, and the verifiers are not
advisory. If one blocks something that is genuinely correct, that is a bug in the
verifier — say so in the issue rather than working around it.
